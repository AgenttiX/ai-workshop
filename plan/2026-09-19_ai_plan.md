This is a working document: times are estimates and the exercises are drafts in this repository.

## 1. Summary
- **What:** a hands-on workshop that shows scientists how AI is *actually* used effectively in 2026:
  not chat windows, but agentic harnesses with access to files, tools and the terminal.
- **Who:** researchers and students at the Kumpula campus, primarily physics.
  No prior AI experience required, but participants must be able to run Python in an IDE.
- **When:** target early November 2026 (start of period II), before Hippe leaves for the USA on 2026-11-26.
- **Where:** D101 (organizers can circulate among the participants, screens on every level).
- **Format:** 2 h session + 15 min break + 2 h session, in English.
  The first session is *foundations*, the second is *advanced*. Both include live demos and hands-on exercises.
- **Tools:** Claude Code (CLI + VS Code extension) with the Claude Team plan for scientists.
  Backup: GitHub Copilot with the GitHub Student Developer Pack. Python 3.12, VS Code / VSCodium.
- **Materials:** slides (`slides.html`, reveal.js) and exercises (`exercises/`) in this repository.
  The repository is private until the workshop and public afterwards.
- **Credits:** the slides and exercises are documented well enough that the doctoral programme can award study credits.
- **Ground rule:** philosophical debates are welcome — during the coffee break and after the workshop.

## 2. Learning goals
After the workshop a participant can:
1. Explain what has changed in AI models during 2024–2026 and why a *harness* (agent + tools + context) is
   an order of magnitude more effective than chat.
2. Install and run Claude Code in VS Code, give it a task in a real repository, review its changes and manage permissions.
3. Write an `AGENTS.md` / `CLAUDE.md` for their own project and manage the context window deliberately.
4. Extend the harness with skills, hooks, subagents and MCP servers, and know when each is the right tool.
5. Make a research code base "AI-ready" with tests, linting, type checking and CI so that the agent catches its own mistakes.
6. Judge when *not* to use AI, and how to use it without losing their own understanding.

### 4.2 Theory: the state of AI in 2026 (25 min, Hippe) + honest caveats (10 min, Mika)
This block is for the part of the audience that has not followed the last 2–3 years. "Lay out the facts."

**Part A — What changed (Hippe, ~15 min)**
- The timeline: ChatGPT (late 2022) → tool use and long context (2024) → reasoning models (late 2024–2025)
  → agentic harnesses and hour-long autonomous tasks (2025–2026).
- The key metric: the length of the tasks an AI can complete autonomously has been doubling roughly every
  4–7 months (METR task-horizon studies). Show the plot. TODO: update the figure to the latest METR data before the workshop.
- Models today: Claude 5 family (Fable 5.1, Opus 5, Sonnet 5), Haiku 4.5, OpenAI's and Google's frontier models,
  and strong open-weight models (Gemma 4, Qwen 3.8, Kimi, …) that run on a single workstation GPU.
- Context windows of ~1M tokens: a whole codebase or a paper's LaTeX + data analysis in one session.
- Science examples: "the Navier–Stokes result was not obtained by asking a chatbot, but by agents".
  TODO: add the exact reference (the result Antti mentioned in the kickoff email) and 1–2 other examples from physics.

**Part B — Chat vs. harness (Hippe, ~10 min)**
- Definition: harness = model + tools (read/write files, shell, web, MCP) + context management + permission loop.
- Why file access matters: the model sees your actual code, data and errors instead of what you paste.
- Why context management matters: the model only knows what's in the context window;
  the harness decides what goes in (files, tool output, memory, `AGENTS.md`).
- The landscape: Claude Code, OpenAI Codex, GitHub Copilot, Cursor, Antigravity, OpenCode;
  plus chat products (Claude.ai Projects, ChatGPT). Cloud sandboxes exist but a local harness on your own
  machine is more capable (from the meeting: mention cloud first, then say local is better).
- Why we chose Claude Code for the exercises: best agentic performance in our experience, VS Code integration,
  the Claude Team plan for scientists, and the same skills/hooks/agents concepts exist in the others.

**Part C — Honest caveats & how to use AI wisely (Mika, ~10 min)**
Showing the downsides gives credibility (from the meeting).
- Hallucinations still happen — now with confidence and at scale. The remedy is verification built into the
  workflow (tests, type checks, cross-checks), not trust. This is the theme of session 2.
- Sycophancy: the model tends to agree with you. Ask for critique explicitly.
- Security: an agent with shell access is a user on your machine. Permission modes, sandboxing, never paste secrets,
  be careful with prompt injection from web pages and papers.
- Cost and rate limits: Team plan quotas, local models as a fallback.
- Skill atrophy and understanding: "How do I use AI without losing my own understanding of physics?"
  Suggested practice: let the agent do the mechanical parts, but *read* everything before it goes into a paper.
- Incentives: the competition may lead to "AI or perish". We don't have an answer; we have a coffee break.
- Ethics of providers, data handling, university guidelines. Keep it to one slide; philosophy goes to the break.
- 5 min Q&A.

### 6.3 Making your project AI-ready (20 min, Mika)
Based on Mika's [unit testing & CI/CD lecture](https://github.com/CFT-HY/unit-testing-ci-cd) and PTtools.
The goal: **the agent fixes its own hallucinations and mistakes before showing you the result.**

- Why: an agent that can run tests, a linter and a type checker gets a feedback signal. Without them,
  it can only *believe* the code works.
- The four pillars and what they give the agent:
  1. Unit tests (`pytest`) — "does the physics still hold?" (regression tests from current output + literature values)
  2. Linting (`ruff`) — style and bug patterns, instantly
  3. Type checking (`pyrefly`) — catches wrong shapes/units of arguments across the codebase
  4. CI (GitHub Actions) — the same checks on every push, including the agent's
  Plus packaging & a README detailed enough that *the agent can install and run the project from the instructions alone*.
- Live demo (Exercise 04): `exercises/04_ai_ready/fitting.py` has no tests, no types and a few lint issues.
  Ask Claude: *"Add type hints, docstrings and unit tests; run ruff, pyrefly and pytest and fix what they report."*
  Show the loop: it runs the tools, reads the errors, fixes, re-runs. Then show `pyproject.toml` and `.github/workflows/ci.yml` of this repository as a template to copy.
- `AGENTS.md` should list the commands (`pytest`, `ruff check`, `pyrefly check`) — show this repository's file as an example.

|---|---|
