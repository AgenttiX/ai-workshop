# Slide themes

Custom [reveal.js](https://revealjs.com/) themes for `slides.html`. Each theme is a drop-in replacement for the built-in `sky` theme: replace the `sky.min.css` link of `slides.html` with e.g.

```html
<link rel="stylesheet" href="themes/ember.css">
```

| Theme        | Look                                                                                  |
|--------------|---------------------------------------------------------------------------------------|
| `paper.css`  | Light. Lab notebook on graph paper: IBM Plex serif headings, deep blue accents.       |
| `clay.css`   | Light. Warm cream with terracotta and slate blue, in the colours of the Claude apps.  |
| `ember.css`  | Dark. Matches the poster: warm charcoal, orange titles, teal callouts.                |
| `latent.css` | Dark. Deep ink blue with a faint dot grid ("embedding space"), cyan and violet.       |

In every theme the definitions (`.def`) stay orange, as the slides refer to them as "the orange boxes".

## Structure
- `_base.css` contains the rules shared by all themes: the equivalent of the reveal.js theme template, and the styles of the custom components of `slides.html` (`.callout`, `.def`, `.loop`, `.harness`, `.prompt-box`, inline code). Those use `.reveal .slides` selectors so that they override the inline `<style>` of `slides.html`.
- Each theme file imports the fonts from Google Fonts and `_base.css`, and sets only CSS custom properties: the `--r-*` variables of reveal.js and the `--t-*` variables documented in `_base.css`. To make a new theme, copy one of them and change the colours.

The dark themes put figures and iframes on a white card and the model logos on a light chip, since the plots and some of the logos are drawn for a light background.

## Decorations of the latent theme
`latent.css` adds AI-themed details on top of the colours:

- **Graphics**, as SVG files in `latent/`, drawn on the background layer of reveal.js. reveal.js copies the classes of each `<section>` to its background, so the class of the slide selects the graphic:
    - all slides except the non-divider `.center-slide` ones: a small neural network in the top-right corner (`corner.svg`)
    - `.center-slide` (title, "Questions?", coffee break, "Thank you!"): a neural network across the slide, faded out behind the text, with a few glowing activation paths (`title.svg`)
    - `.divider`: the attention of two tokens to the previous tokens, as arcs above a row of tokens (`divider.svg`)
    - a `data-background-*` attribute on a slide replaces the graphic, except for the corner network.
- **CSS effects**: a blinking cursor after the `.center-slide` titles, like a model streaming its answer (static in the PDF and with `prefers-reduced-motion`), gradient text on the section dividers (solid cyan in the PDF), gradient bars on the callouts and the progress bar, and a faint glow on the diagram boxes.

The SVG files are generated by `latent/generate.py` with a fixed random seed (standard library only). Change its parameters and run `python3 themes/latent/generate.py` to redraw them, instead of editing the SVG files by hand.

Avoid SVG filters and masks and CSS `filter` in the decorations, e.g. a blur for a glow: Chromium rasterizes them when printing, which made the PDF of the slides over 30 MB. The glows are wide, faint strokes instead.
